# 3×3／4×4／5×5 數字滑塊比較

開啟 `http://127.0.0.1:15414/puzzle`（15413 同樣提供）。原本 100 筆分類頁 `/benchmark` 上方也有入口。

1. 設定盤面編號、合法打亂次數、每邊步數與時間上限。
2. 輸入自己的 Jev API key，確認模型名稱，按「開始 · 兩邊一起拼」。設定區自動收合。
3. 兩邊從同一盤面出發，各自選下一步；完成、達上限、請求失敗或使用者停止後結束。
4. 可按「只測 urJev」做本機測試，或匯出逐步 JSON。每次重新開始重設為該編號的相同起始盤面。

尺寸可在設定中選擇 3×3、4×4 或 5×5。目標為每列左到右、再上到下排列數字，右下角留空；每一步只能將空格與相鄰數字交換。打亂從目標盤面做合法移動，確保可解，且避免直接倒走；打亂次數並非最短解長度，也不是均勻抽樣所有盤面。

## 比較方式

每一步都向模型詢問一個 `choice` 問題，選項是合法的空格方向（up/down/left/right）。State 包含目前盤面、目標、合法移動及最近八步；不提供打亂路徑、最短路徑或搜尋演算法建議。urJev 使用 `/v1/systemone/oneforward`；Jev 透過既有 `/api/benchmark/jev` 代理到官方 SystemOne API。兩邊第一個 State 與 questions 完全相同，後續依各自決策產生不同盤面。

每邊逐步循序請求，兩邊一起啟動，使用同一個起跑時鐘。不設動畫等待時間。允許模型倒走，重複盤面如實計數，不自動改動答案；不合法、缺失或失敗回應即停止該邊，不以本機求解器補救。另一邊可繼續。

先完整達到目標的模型獲勝；若都沒有完成則沒有勝者。歸位格數與格距只作視覺觀察。這比較的是「模型逐步決策＋網路＋服務」的整體表現，不代表純推論引擎速度，也不能用一局推論全面優劣。建議用多個固定盤面編號重跑比較成功率、總耗時及步數。

## 紀錄與成本

畫面顯示步數、請求數、總時間、上一步回應、平均回應、重複盤面。匯出包含起始盤面、目標、限制、模型、結束狀態、每步前後盤面、方向、交換數字、請求耗時、累計時間及可取得的 usage。

單步 request_ms 包含瀏覽器 fetch 與 JSON 解析；總時間包含 API 等待及畫面處理。provider_ms 的定義不同：urJev 為本地 server_ms，Jev 為本地代理量到的官方 API 來回，不能當成相同的純模型時間。取消或逾時後的回應不再移動棋盤。

每步一次 API，預設每邊最多 40 次、2 分鐘；單一請求最多等 30 秒。Jev key 僅存於本頁欄位與執行期間的記憶體，經代理送往官方，不放入匯出或 localStorage。停止瀏覽器等待不保證取消官方已開始的工作，仍可能計費。沒有 key 時不會發出雙邊請求；可使用單邊本機測試。

## 驗證

自動測試涵蓋可解性（奇數寬盤面逆序數）、重現盤面、不修改另一邊、合法方向、同一初始 payload、單步完成、無效回應、循環步數限制、逾時及停止後不套用晚到答案，並檢查靜態路由載入不發出 API 請求。Jev 的真實帳戶端到端比較仍需使用者輸入 key；本次沒有執行付費官方請求。
