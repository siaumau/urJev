# 保留模型輸入的驗證器快取調校

2026-09-22。只調整 `src/systemone.js` 的 Ajv 驗證器編譯：依完整 schema 字串快取，LRU 上限 128 個。沒有快取 State、提示詞或答案；沒有改動模型、精度、提示詞、輸出格式或 GPU 設定。

原本每題每次建立 Ajv 並編譯 schema；五題暖機後仍需約 18–24 ms。快取命中後前置準備約 1 ms 以下（由整體時間扣除四捨五入的推論時間估算，因此有誤差）。首次或不同 schema 仍需編譯。

獨立前後各 12 輪，含準備時間的中位數為 552.6 → 492.3 ms。另做同一服務交錯十輪，中位數 578.4 → 500.0 ms，範圍分別為 554.8–601.7 與 478.8–579.4 ms。整體差異大於編譯時間，不能全部歸因於快取，GPU／排程波動尚未隔離。

正式本機 HTTP 服務重啟套用後，五次完整 HTTP 等待為 558、580、611、524、566 ms；server_ms 為 530、577、608、522、564 ms。API 仍有波動，不能宣稱 Playground 穩定低於 500 ms。

## 品質檢查與限制

交錯測試逐次確認傳入模型的 messages 與 schema 完全一致。另比較十筆回饋，每筆五題。情緒／退款／停止續訂三項，共 30 個新舊判斷全部相同，原有兩筆 mixed 情緒仍判 negative。檢查不能證明所有資料準確率不變。

也觀察到不完全一致的模型輸出：中性詢問新增課程的主題，基準為 service、候選為 other；條件式取消的 frustration 分數 1.7 → 1.8；混合情緒權重不同但最高分類仍 negative。先前以所有答案完全相同作斷言的檢查失敗，後續保留完整差異而非忽略。相同模型輸入在此環境未能保證逐位一致；不能把語意三項相同解讀為全部權重、分數相同。

25 項單元測試通過，新增涵蓋 State 更新、不同選項與包裝 schema 的驗證隔離，以及非法權重拒絕。

原始測量保存在 `docs/benchmarks/validator-cache/`。`node scripts/benchmark-preparation.js REPORT_NAME` 可對當前版本收集 2 次暖機及 12 次含準備時間測量。交錯比較基準取自提交 cb64f9f 的 systemone.js；只替换 engine import 路徑以便與修改版在同一 Node 程序執行。
