# urJev 測試頁面啟動與操作手冊

這份文件整理目前可直接在瀏覽器使用的三個頁面：Playground、100 筆 Benchmark 與拼圖測試。模型服務與網頁服務重開機後都需要重新啟動。

## 快速啟動

在 `F:\sideproject\urJev` 開兩個 PowerShell 終端。

終端一啟動 Qwen3＋vLLM 模型，服務埠為 `18000`：

```powershell
npm run model:vllm
```

看到模型完成載入後，在終端二啟動網頁與 API：

```powershell
npm start
```

`.env` 預設 `PORT=15413` 時，使用以下網址：

| 頁面 | 網址 | 用途 |
|---|---|---|
| Playground | `http://127.0.0.1:15413/` | 自訂 State／Problem，查看結構化結果與推論時間 |
| Benchmark | `http://127.0.0.1:15413/benchmark` | 跑 100 筆、500 個判斷，逐題比對 urJev 與 Jev |
| Puzzle | `http://127.0.0.1:15413/puzzle` | 測試逐步規劃、模型競賽與人工操作 |

若要改用目前常用的 `15414`，在第二個終端執行：

```powershell
$env:PORT = '15414'
npm start
```

對應網址改成 `http://127.0.0.1:15414/`、`/benchmark`、`/puzzle`。15413 與 15414 是同一個 Node 服務的不同啟動埠，平常不需要同時啟動。

## 確認服務正常

```powershell
Invoke-RestMethod http://127.0.0.1:18000/v1/models
Invoke-RestMethod http://127.0.0.1:15414/api/health
```

網頁服務的 health 應顯示 `ready: true`、`backend: vllm` 與目前模型名稱。若使用 15413，將第二個網址的埠改成 15413。

## Playground

開啟首頁後：

1. 在 State 貼入待分析資料。
2. 在 Problem 定義 `choice`、`noul` 或 `score` 題目。
3. 按執行查看每張結果卡、機率、伺服器時間與完整 JSON。
4. Qwen3-8B 與 vLLM 必須先在 18000 就緒。

Playground 適合少量手動測試新的分類規則。正式比較應使用 Benchmark，避免只看單一案例。

## 100 筆 Benchmark

開啟 `/benchmark` 後可選：

- `只跑 urJev`：不需要 Jev API key。
- `開始 100 筆比較`：需要自己的 Jev API key，會產生 100 次官方 API 呼叫。

測試完成後：

- 點擊任一表格列，可查看 State、完整 Problem、標註答案與兩邊逐欄結果。
- 可篩選全部題目、任一模型答錯、urJev 答錯或 Jev 答錯。
- `複製 JSON` 會把完整結果放入剪貼簿。
- `下載 JSON` 會保存題目、標註、答案、正確性、延遲與 token 資訊。

Jev key 只保留在當前頁面記憶體；重新整理後會清除，也不會寫入匯出檔。

## 拼圖測試

開啟 `/puzzle` 後可選擇 3×3 到 10×10、打亂次數、步數與時間上限。

urJev 模式：

| 模式 | 行為 |
|---|---|
| 純模型 | 每一步完全由 Qwen3-8B 選擇，最能反映原始模型能力，但可能循環 |
| 模型＋規劃建議 | 規劃器提供建議，模型保留最後決定權 |
| 強制規劃路徑＋模型驗證 | 規劃器決定移動，模型仍被呼叫以驗證；會保留模型延遲 |
| 本機規劃器基準 | 不呼叫 LLM，只測本機搜尋速度，不能當成模型速度比較 |

操作按鈕：

- `開始 · 兩邊一起拼`：urJev 與 Jev API 使用相同起始盤面。
- `只測 urJev`：只執行左側，不需要 Jev key。
- `手動玩右側`：只跑 urJev 結束後啟用。右側會回到相同起始盤面，點擊空格旁的數字即可人工解題。
- `匯出紀錄`：保存模型與人工逐步移動、時間及重複盤面。

大型盤面使用有限 Beam Search，現在設定為深度 20、每層最多 512 條候選，並避開本局已訪問盤面。這能提高成功率，但不保證每個盤面都能解出；更大的搜尋設定會增加 CPU、記憶體與每步等待時間。

## 常見問題

### 顯示 `ready: false`

先確認 18000 的 vLLM 已完成模型載入，再重新整理網頁。

### 頁面無法開啟

確認啟動網頁時使用的埠。`npm start` 讀取 `.env`；手動設定 `$env:PORT='15414'` 只對該 PowerShell 終端有效。

### urJev HTTP 400

通常代表 Problem schema 或候選數量不合法。重新整理頁面套用最新版後再測；若仍發生，查看頁面錯誤訊息與服務終端輸出。

### 模型陷入循環

純模型或有限搜尋都可能回到舊盤面。頁面會偵測連續重複並停止，避免持續消耗請求。若要測人類解法，可先只跑 urJev，再使用右側人工模式。

### 停止服務

在對應終端按 `Ctrl+C`。建議先停止網頁服務，再停止 vLLM 模型服務。
